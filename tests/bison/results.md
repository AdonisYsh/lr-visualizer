## Engine observations

Not disagreements with Bison - the translated numbers agree - but worth knowing:

- probe-three-actions.txt LALR(1): engine lists 2 conflicts over 1 conflicted cells (a cell holds 3+ actions)
- probe-three-actions.txt CLR(1): engine lists 2 conflicts over 1 conflicted cells (a cell holds 3+ actions)

On a cell with three actions the engine lists one conflict per colliding action, not one per cell, and labels both `shift-reduce`. This tool counts conflicts per colliding action, as the engine's verdict does. For all thirteen presets that is also the number of conflicted cells, because none of them, under any variant, has a cell with more than two actions.

## How Bison counts differently

Each rule is applied identically to every row; a difference that needs anything else is reported as a disagreement.

1. **One extra state, always.** Bison augments with `$accept: S $end` and actually *shifts* `$end` into a final state `$accept: S $end .`, where it accepts. We augment with `S' -> S` and write `accept` into the `$` column of the state holding `S' -> S .`, so that last state does not exist for us. Bison's count is therefore ours + 1. Offsets observed over all 28 runs: +1.
2. **Conflicts are counted per token per extra action.** Bison, per state, counts one shift/reduce for each token on which a shift meets at least one reduction, and `n - 1` reduce/reduce for each token on which `n >= 2` reductions meet. A cell holding one shift and one reduction, or two reductions, is one conflict either way, and that is every conflicted cell in every preset. The two ways of counting can only part on a cell with three or more actions, which no preset has, so the probe row builds one: shift + reduce + reduce on `a` is 1 S/R + 1 R/R for Bison. The script does not compare the engine's own count with Bison's; it translates the engine's ACTION table cell by cell with exactly this rule and compares totals *and* the per-state distribution. Our `accept` is treated as Bison's shift of `$end`.
3. **State numbering differs.** Bison numbers its states in its own order, not ours (ours follow the order in which symbols first appear in the grammar), so conflicts are compared as a multiset of per-state `(S/R, R/R)` pairs rather than by state number.

Two things that look like they might matter, and do not:

- **Default resolution.** Bison resolves an unresolved shift/reduce in favour of the shift and a reduce/reduce in favour of the rule written first. That decides what the generated parser does; it does not change the number of conflicts reported, which is all that is compared here. Our table keeps every colliding action in the cell instead.
- **Default reductions.** `lr.default-reduction` is `most` for LALR and `accepting` for canonical LR (Bison manual, *Default Reductions*). Default reductions are chosen after conflicts are counted and only compress the table, so neither the state count nor the conflict count moves. The manual describes `canonical-lr` as the canonical LR tables of Knuth 1965, and the +1 offset holding on every CLR(1) row is consistent with that.

The grammars Bison was given are in `grammars/`, one per preset plus the probe, generated from the engine's own parse of `examples/*.txt`.
